# Repository Guidelines

## Project Structure & Module Organization

GWBackground.jl is a Julia workspace for astrophysical stochastic gravitational-wave background modeling and inference. The package entry point is `GWBackground/src/GWBackground.jl`, which includes and exports reusable physics and array kernels. The caller-owned model contract, spectral-density forward model, Turing/AdvancedHMC wrappers, and sampling helpers live in `GWBackgroundInference/`. Canonical concrete adapters live in `GWBackgroundImportanceModels/`; its BNS Madau–Dickinson adapter is the built-in production model, while caller-owned adapters remain supported. Core modules live in `GWBackground/src/`, with detector-specific code under `GWBackground/src/detector/`. Tests live beside each package and are listed from its `test/runtests.jl`. Detector definitions and noise curves are stored in `GWBackground/assets/detector/`. **Production MCMC is notebook-first** (see `notebooks/mcmc.jl`): load a waveform catalog with [`load_catalog`](GWBackground/src/catalog/io.jl), derive the inclination-averaging convention with `average_mode(catalog)`, keep `catalog.samples` (which already carries `redshift` and `luminosity_distance`), `catalog.polarization_power`, and fiducial hyperparameters explicit, prepare the model with `prepare_bns_madau_dickinson_model`, slice `catalog.frequencies` and the rows of `catalog.polarization_power` to the analysis band (band selection is caller-owned; the catalog carries no mask), compute the network `effective_psd` on the banded frequencies, synthesize `observed` at the fiducials with `forward_model(model, polarization_power, samples, fiducials; average_mode).spectral_density` when there is no external spectrum to fit, and construct the Turing model directly: `GWBackgroundInference.gwbackground_importance_turing_model(model, polarization_power, samples, prior, observed, frequencies, effective_psd, observation_time, average_mode)` — the prior declares **all** hyperparameter names, and fixing one is Turing conditioning, `model | Base.structdiff(fiducials, sampled_prior)` (`R₀` is pinned at its fiducial unless named in `sample_only`) — sample with NUTS, and save chains to netCDF via `GWBackgroundInference.rename_posterior_for_netcdf(chain)` + `InferenceObjects.convert_to_inference_data` + `InferenceObjects.to_netcdf` (see `scripts/run_mcmc.jl`). Developer utilities (profiling, benchmarks) live in `scripts/` (for example `profile_turing.jl`). Pluto and Jupytext notebooks are under `notebooks/`.

Note: the package is still in the prototyping phase, so breaking changes are allowed and backwards compatibility is not a concern.

## Build, Test, and Development Commands

- `just fmt`: format the repository using JuliaFormatter.
- `just test`: run the package test suite through `Pkg.test()`.
- `just pluto`: instantiate the notebook environment and launch Pluto.
- `julia --project=notebooks -e 'using Pkg; Pkg.instantiate()'` then open `notebooks/mcmc.jl` in Pluto for the canonical MCMC workflow.

If `just` is unavailable, use the Julia commands in the `justfile`, for example `julia --project=GWBackground -e 'using Pkg; Pkg.test()'`.

## Coding Style & Naming Conventions

Target Julia version is 1.12. Formatting is controlled by `.JuliaFormatter.toml` with `style = "sciml"`; run `just fmt` before committing. Keep code type-stable where practical, especially in likelihood, redshift, and spectral-density paths.

Use existing Unicode scientific identifiers, including `Ωm`, `Ξ₀`, `Ξₙ`, `γ`, `κ`, `Λ`, `R₀`, `χ₁`, and `χ₂`. Live inference hyperparameters are a flat `NamedTuple`. **The model contract is one documented callable**, `merger_rate_and_log_weights_fn(Λ, samples) -> (rate, log_weights)` — no abstract type, no generic function to add methods to. A prepared model is a functor (`(m::M)(Λ, samples)`), which keeps full dispatch and type parameters, as `BNSMadauDickinsonImportanceModel` does for cosmology and propagation; an ad-hoc model is a plain closure. Because the seam is a callable, `GWBackgroundImportanceModels` does **not** depend on `GWBackgroundInference` at all. Hyperparameter *names* are declared by a caller-owned prior `@model` (`prior_model`), never by the SGWB likelihood model: its `~` sites control Turing variable creation order (embedded via `to_submodel(prior_model, false)`), and a name the callable needs but the prior model omits is a `KeyError` on `Λ.name` at the first evaluation. Fixing a hyperparameter is Turing conditioning at the call site — `model | (; R₀ = fiducials.R₀)` — so the chain carries exactly the sampled variables by construction; a pinned value outside prior support scores `-Inf` at the first evaluation. There is deliberately no `hyperparameters(model)`, no `validate_fiducials`, and no model-building or conditioning wrapper — callers construct `gwbackground_importance_turing_model` inline and condition it themselves. Test files follow `test_<area>.jl`, such as `test_redshift.jl`.

## Testing Guidelines

Tests use Julia's standard `Test` framework and are orchestrated by each package's `test/runtests.jl`. Add new test files to the relevant runner; otherwise they will not run in CI or `Pkg.test()`. Prefer focused numerical tests with explicit tolerances for cosmology, redshift integrals, likelihoods, and interpolation behavior. Minimal catalog fixtures for core tests are written on demand via `parity_catalog_dir` (see `GWBackground/test/parity_test_cache.jl`), which synthesizes v1 polarizations from a desired polarization power with `parity_polarizations`; the `:sampled_inclination` variant exercises the `CatalogInclination()` branch of `average_mode`. Cross-language polarization-power parity against the Python stack is covered by a gitignored fixture pair regenerated with `../astrogwb/.venv/bin/python3 scripts/generate_catalog_parity_fixture.py` (the test skips when absent, matching the GWFast ORF fixture convention). Physical adapter parity, cache, AD, and concrete Turing integration tests belong in `GWBackgroundImportanceModels/test/`; generic interface and contract tests belong in `GWBackgroundInference/test/`. The load-bearing assertions for amplitude marginalization are the two *equivalence* tests — the marginalized model's `logjoint` must equal the numerically integrated general model's, **with no leftover additive constant** (`GWBackgroundInference/test/test_turing.jl`, and again against the real BNS adapter in `GWBackgroundImportanceModels/test/runtests.jl`) — plus the multiplicative-property test asserting `forward_model` really does factorize in `H0` and `R₀`. Keep the noise scaled to the signal in these: an arbitrary PSD puts `ρ` at 1e21, where the identity tests floating-point noise instead of the marginalization.

Run `just test` before opening a pull request. For narrow changes, also run the closest individual test file during development with `julia --project=GWBackground GWBackground/test/test_<area>.jl`.

## Commit & Pull Request Guidelines

Recent history uses Conventional Commit-style subjects: `feat:`, `chore:`, `refactor:`, `perf:`, and `refactor!:` for breaking changes. Keep subjects imperative and scoped to one logical change.

Pull requests should include a short summary, testing performed, and links to relevant issues or discussions. Note behavior changes, fixture updates, performance-sensitive changes, and any compatibility impact. Include plots or screenshots only when changing notebooks or user-facing visual outputs.

## Architecture Notes

The inference layer is **cosmology-agnostic**. The main inference flow is: load `catalog.h5` with `load_catalog`, restructure per-event samples, keep raw catalog polarization power and fiducial hyperparameters explicit, prepare an importance model, compute the detector network's banded [`effective_psd`](GWBackground/src/detector/effective_psd.jl), then run importance weighting, spectral-density evaluation, and posterior sampling. The sampler boundary belongs to `GWBackgroundInference`; reusable astrophysical adapters belong to `GWBackgroundImportanceModels`; `GWBackground` and its lower-level siblings contain the kernels below them. The two are joined by a callable, not a dependency: `GWBackgroundImportanceModels` imports nothing from `GWBackgroundInference` (it is a test-only extra there).

**Detector state never belongs in the importance model** — and that now includes the observation time, which cancelled algebraically out of the rate (`1e-9·R₀·∫·T / (T·JULIAN_YEAR_SEC)`). The local merger rate `R₀` (Gpc⁻³ yr⁻¹) is an ordinary hyperparameter read as `Λ.R₀` and baked into `MadauDickinsonSourceFrame` / `source_frame_distribution` with the Gpc³→Mpc³ and yr→sec conversions, so [`normalizer`](GWDistributions/src/base/interpolated_1d_distribution.jl) of the detector-frame [`RedshiftInterpolatedDistribution`](GWDistributions/src/redshift/base.jl) is already events/sec. Fix `R₀` by conditioning (`model | (; R₀ = fiducials.R₀)`) and sample it by naming it in `sample_only`.

[`forward_model`](GWBackgroundInference/src/forward.jl) is the single implementation of the forward pass, shared by the `@model` body and the caller-side synthesis of `observed` at the fiducial point. Scoring a point is `Turing.logjoint(model, θ)` — there is deliberately no second likelihood implementation to drift from the first. Respect matrix layout conventions: cached polarization-power arrays are `(nfreq, nsamples)` in memory; full catalogs use intrinsic proposal vectors `(nsamples, n_intrinsic)`, while the canonical BNS path reduces samples to slim `NamedTuple` columns (`redshift`, `luminosity_distance`).

**Catalog format.** `catalog.h5` is a `waveform_catalog` v1 file — the same format the Python `astrogwb` package consumes, generated by `astrogwb-generate-waveform-catalog`. Format IO belongs to `PlusCross.jl` (an unregistered git dep declared in `GWBackground/Project.toml`'s `[sources]`); `load_catalog` only reduces the stored complex `/polarizations/{plus,cross}` to `|h₊|² + |h×|²`, returning an [`SGWBCatalog`](GWBackground/src/catalog/catalog.jl). The frequency axis is *read from the file*, never derived from `(duration, sampling_frequency)`; the file's band edges are discarded — callers slice the arrays to their analysis band themselves. PlusCross exports both `WaveformCatalog` and `load_catalog`, so it must be `import`ed and qualified, never `using`'d. HDF5's C-order `(nsamples, nfreq)` datasets read into Julia as `(nfreq, nsamples)` with no transpose.

**Two likelihoods.** [`gwbackground_amplitude_marginalized_turing_model`](GWBackgroundInference/src/turing_model.jl) integrates one strictly *multiplicative* hyperparameter out of the Gaussian likelihood instead of sampling it, removing the long curved amplitude–shape degeneracy NUTS handles worst. Selected by `likelihood = "amplitude_marginalized"` + `amplitude_parameter` in a schema-v3 [`MCMCConfig`](GWBackgroundInference/src/config.jl). The math and the grid-versus-support asymmetry are documented in [`amplitude.jl`](GWBackgroundInference/src/amplitude.jl); the σ-space contractions reuse [`GWBackground.inner_product`](GWBackground/src/snr.jl), which already carries the `2 T Δf` prefactor — re-deriving it would make `ρ²` wrong by `2T`. Only `H0` (`f = φ⁻¹`) and `R₀` (`f = φ`) are exactly multiplicative for the BNS adapter; `GWBackgroundImportanceModels.bns_amplitude_scalings` is the only sanctioned source of those scalings, and the property is asserted against the real `forward_model` in that package's tests. The marginalized parameter is pinned **inside** the model (never conditioned at the call site) and has no latent variable, yet still lands in the saved posterior via [`reconstruct_amplitude`](GWBackgroundInference/src/reconstruction.jl) — so use `posterior_params(cfg)`, not `sample_only`, to describe the output file. The reconstruction's prior, fiducial, and `amplitude_fn` must be *exactly* the model's — a mismatch is silent — but the grid is only quadrature accuracy: `quantile`/`rand` refine a localized mesh from it internally (see `_fine_mesh` in `GWBackgroundInference/src/amplitude.jl` and the analysis in `QUADRATURE_NODES.md`), so the default 1024 prior-span nodes suffice even at ρ ≈ 400. Always check `quadrature_effective_nodes` (≳ 30): it measures the refined mesh the draws come from, and an unresolved conditional still yields a finite, plausible log evidence — the low diagnostic is the only symptom there is.

**Recorded quantities and netCDF names.** Both models publish derived quantities as `:=` sites, which is free — the right-hand side is evaluated unconditionally and Turing already re-evaluates the model once per saved draw. Names and definitions match the Python `astrogwb` stack (`total_merger_rate`, `importance_relative_ess`; plus `template_merger_rate`, `amplitude_mle`, `template_optimal_snr` under marginalization) so the two projects' netCDFs are diffable. Note this makes `FlexiChains.parameters(chain)` include names with no fiducial value — filter before pairing against `FIDUCIALS`. Unicode hyperparameter names stay put in Julia code, config TOML, and tests; [`rename_posterior_for_netcdf`](GWBackgroundInference/ext/GWBackgroundInferenceFlexiChainsExt.jl) maps them to ASCII **on write only**, via `NETCDF_PARAMETER_NAMES`. That helper and `merge_into_posterior` live in a `FlexiChains` package extension (fold reconstructed amplitude into the chain, rename, then `convert_to_inference_data` + `to_netcdf`), keeping `FlexiChains` / `InferenceObjects` out of the inference package's hard deps.

**Inclination averaging is a catalog property, not a constant.** `spectral_density` scales by [`inclination_factor`](GWBackground/src/spectral_density.jl) of an `AbstractAverageMode` token: `AnalyticInclination()` (catalog is face-on, apply `2/5`) or `CatalogInclination()` (catalog samples ι, apply `1`). `average_mode(catalog)` derives it from the catalog's `inclination` column, falling back to `AnalyticInclination()` when the column is absent. Pass **one** resolved value to both the `forward_model` call that synthesizes `observed` and `gwbackground_importance_turing_model` — splitting them biases the fit by a constant factor with no other symptom. Config names (`"analytic_inclination"`, `"catalog_inclination"`) match astrogwb's `AverageMode` literals.
